Columbus Housing Pipeline

Paused

Weekly county home-sale reports turned into parcel-level data, verified against the county's own counts. Paused while source data for two more counties is added by hand.

Pipeline, source to silver

  1. County reportWeekly sales page, removed by the county after about 30 weeks
  2. Save and parseEvery page stored first, then parsed into parcel rows
  3. Quality gate23 rules, fail or warn, checked against the printed count
  4. SQL ServerKeyed on county, parcel, date, and price
  5. DatabricksAppend-only bronze, then silver, reconciled to SQL Server

  • Safe re-runs

    Exports move a high-water mark only after an upload succeeds. Running anything twice adds nothing.

  • Data you can't get back

    Pages vanish from the county site, so each one is saved before parsing. Parser fixes replay over saved pages with no network.

  • Failing loudly

    A failed rule stops the weekly job before anything lands in Databricks. Exceptions are written down next to the rules.

Python, SQL Server, Databricks, GitHub Actions. Databricks runs on Free Edition: tools shown end to end, not production scale. View the repo

NFL Injury Analyzer

Active

A dimensional warehouse of NFL player availability and injuries since 2010, built from nflverse data.

Pipeline, source to star schema

  1. ExtractRosters, players, games, injuries, with retries and a manifest per file
  2. Raw loadText landing tables with row-count reconciliation per batch
  3. StagingRules driven by the data profile findings
  4. Dimensions and factsPlayer-week grain, SCD2 teams, injury episodes
  5. ServePower BI over the star schema

  • Inferred is labeled inferred

    The source has no injury location, so onset venue is inferred and each row records its inference method.

  • Replayable by design

    Raw files are kept with url, checksum, and row count, so any run can be replayed.

  • Profiled before modeled

    Team codes differ by era and early rosters have duplicate keys. The staging rules come from those findings.

Python, SQL Server, T-SQL. Built and unit-tested: extract and raw load. Next: staging, dimensions, facts. View the repo
